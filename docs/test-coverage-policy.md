# Required test coverage policy

The complete check has a 600-second budget with dependencies and tools cached. Critical failure detection determines coverage; test counts and Cartesian products do not. See [the machine-readable policy](test-coverage-policy.json) for exact retained detector names and implementation state. The initial reductions below passed their selected Memory/SQLite/PostgreSQL histories serially and at four slots, with owned fixture/container cleanup verified. The full schedule and ten-minute measurements remain pending.

Each costly family records the failure, production owner, required backend, retained detector and reason a removed dimension adds no distinct detection. Use KEEP, MOVE-CHEAPER, MERGE or DELETE-REDUNDANT. A unique transaction, SQL parser/constraint, migration, authorization, replay or process-recovery branch needs a required detector at its real owner. Pure malformed-input tables stay cheap and complete at shared validators. Public journeys verify wiring and cold reconciliation rather than repeat storage matrices.

The SQL fault histories call the original assertion helpers unchanged. Before/after-commit and activation uncertainty remain real SQL transactions. Current PostgreSQL fixtures already provide the migrated schema; dedicated migration tests continue using Blank/legacy fixtures. Every independent fault test receives fresh storage. Shared state between independently scheduled histories is forbidden.

The pending corruption table exercises shared `Completed::new`, `Source::metadata`, fence/root-join checks and comparison with inspected metadata. SQLite and PostgreSQL do not implement those checks separately. They do authenticate native storage separately, so each still runs malformed receipt and outcome rejection for ToolClaim, ToolRecovery, FrontendClaim and FrontendRecovery. Stage holds/failures, exact committed-ACK replay, task identity, cleanup and effect counts remain intact in this first reduction.

Further reductions must retain real crash/restart, effect counts, concurrency, leases, cancellation, cleanup, migrations, distinct backend SQL/serialization, limits, feature absence, redaction, WASM and embedding boundaries. Known regression reproductions remain required. Do not hide essential coverage in ignored/nightly suites or pass with retries, relaxed durability or increased deadlines.

Before qualification, audit the final selected manifest against the policy and verify three consequential reductions with temporary meaningful faults. Record failure and exact restoration as implementation evidence; no permanent mutation framework is required. A faster failed or partial check does not meet the budget.
