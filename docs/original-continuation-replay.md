# Original continuation reconciliation

Replaying an approval, native tool or frontend continuation, including its explicit Unstarted recovery, uses its original operation identity and captured request semantics. A matching receipt returns metadata and never creates another execution handle. Changed run, continuation generation, revision, supplied choices or frontend resolver assertions are rejected.

For new continuation births, the native stores authenticate the complete original frozen batch against an independently protected input source, its suspension receipt and normalized indexed event before extracting its plan fingerprint. PostgreSQL schema 20 and SQLite schema 16 add these sources; earlier continuations retain their ordinary legacy reconciliation semantics without gaining protected-input coverage. They bound that selected batch before transferring or cloning it. This read does not decode the mutable Run, checkpoint, current answers, owner tokens, or cross-kind handoff. Oversized unrelated current fields therefore do not require loading a private checkpoint merely to reconcile a receipt.

Custom stores that implement native continuations must also implement `original_approval_plan` and `original_tool_continuation_plan`. The default is Unsupported. Missing or changed original provenance fails closed; the runtime never initializes factories or dispatches work to recover it. Raw operation receipt lookup remains available independently. Fresh execution still validates the current Run, exact original binding, and native claim/Begin authority.

Original suspension and accepted-answer sources are recorded in the same transaction as their actual original writes. Each source binds the full typed input, receipt, event and exact session/run/continuation generation. This includes checkpoint bodies, human prompts, reply values, resolver assertions, original operation identities and presentation timestamps that older semantic retry hashes may omit. Automatically expired unanswered questions and termination cancellation do not manufacture answer sources. Later answer consumption preserves the original accepted answer.

Current readers corroborate accepted answers and independently retained subjects. Session scans cross-check protected cohorts and current scoped identities before filtering state or barriers. Pure original-plan reads use the original suspension source only, so later answer or current-state damage does not change their selected original input. Existing committed operation lookup remains metadata-only. A legacy continuation cannot freshly register or activate a protected approval successor Driver; these return Unsupported. Ordinary legacy continuation APIs remain available.

Source rows are limited to 4 KiB. Selected original carriers are charged to the enclosing proof before transfer or cloning. Canonical hashing preflights a 5 MiB encoded-size limit, then allocates a bounded temporary JSON tree and serialization; it is not a streaming hash. SQL consistency anti-joins return bounded scalars but may scan scoped database identities. Memory scans borrow retained identity metadata; this does not bound a whole transaction-state clone.

Immutable source/cohort routing and replacement guards apply to new births. Every retained continuation identity, including legacy identities, may be deleted only under the exact session tombstone during scoped purge; erasing and reinserting a legacy identity cannot upgrade its payload provenance. This selected-input protocol does not establish complete historical membership, private grant retention, native Begin enrollment, actual worker/resource joins, or whole-Run resource policy.
